Three test modules share a single `conftest.py` fixture layer:
- `conftest.py` provisions an isolated temp directory via `RAT_DATA_DIR`, bootstraps a real Git repo (`build_fixture_repo`) with a scripted history of 10 commits (c1..c7, fm branch, merge, c9) covering renames, binary files, merges, empty commits, and `.mailmap` author mapping, then exposes `fixture_repo`, `fixture_zip`, and `indexed` fixtures that ingest the repo into the app's SQLite database.
- `test_parser.py` is unit-level: it feeds a byte stream mimicking `git log --numstat -z` output to `app.ingest.parse_log_stream` and asserts parsed commit/file records.
- `test_metrics.py` is golden-value tests against the indexed DB, exercising `metrics.run_view` for summary/files/dirs/authors/timeseries/commits and `authors.merge_authors/unmerge_*` helpers, asserting exact added/removed/churn/modifications counts derived from the fixture history documented in `conftest.py`'s docstring.
- `test_api.py` is end-to-end: it uses FastAPI's `TestClient` against `app.main.app` to upload the fixture zip, poll `/api/repos/{id}` until `ready`, and assert every endpoint path (summary, files, dirs, authors, author-merges, commits, paths, timeseries).
Dependency direction is one-way: tests import `app` submodules (`db`, `metrics`, `authors`, `ingest`, `main`) but never the reverse; the fixture layer owns all Git/database state.
